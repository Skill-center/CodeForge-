# Testing Strategy

**Status:** Accepted Phase 0 · Grows with each phase · Rule: no feature is "done" without its tests running green in CI (spec rules 11/15/16)

---

## 1. Test pyramid

| Level | Tool | Scope | When |
|---|---|---|---|
| Dart unit | `flutter test` | domain, controllers (with fake services), protocol codecs, settings, migrations | every PR |
| Dart widget | `flutter test` + golden files | components, navigation, adaptive layouts (3 breakpoints × orientation), theme switching | every PR |
| Bridge contract | Dart test + vitest, shared JSON fixtures | every message type round-trips; unknown version/type rejected | every PR touching protocol |
| JS unit | vitest | CM6 change-set apply/rebase, protocol validation, search regex semantics | every PR touching editor/ |
| Kotlin/JVM unit | Gradle `test` | host services with fakes; vendored sealed-runtime tests unchanged | every PR touching android/native |
| Android instrumented | `connectedAndroidTest` on emulator | Pigeon channels end-to-end, SAF flows, WebView bridge, lifecycle/process-death | phase gates (no nightly run, §5) |
| Runtime gates | ported `ExecModelTest`/`SealedShellTest` | exec model + sealed userland on API 34/36 x86_64 **and arm64 device** (Firebase Test Lab, ADR-0009) | Phase 4 gate, then every phase gate |
| E2E workflow | `integration_test` | spec §10 scenario: open project → create file → edit → save → run → output → edit → commit | phase gates from Ph. 5/7 |
| Performance | benchmark suite (PERFORMANCE.md) | startup, editor latency, memory, terminal flood, large files | phase gates + release |

Widget tests run the real `EditorHost` against a scripted Dart page (`test/support/fake_editor_surface.dart`) because platform views cannot run under `flutter test`; the scripted page validates every host message with the production protocol code. Files in widget tests come from `MemoryFileService` (`test/support/memory_file_service.dart`), which uses the production path rules and codec, so a refused path or a binary file behaves as on a device; `TestHarness` shares one across restarts of the app within a test. The session store works the same way: `MemorySessionStore`, shared across restarts so a restart sees what the last run journaled. `FlakySessionStore` (`test/support/flaky_session_store.dart`) wraps one to fail or throw on demand. The benchmark screens work the same way, over scripted benchmark pages (`test/support/fake_bench_surface.dart`), and `TestHarness` gives every app-level test a build without benchmark pages.

The benchmark group in the phase gate fails only if a run cannot complete (a page that does not start, a failed scope check, a missing run). Budget misses are recorded in `editor_bench.json` as evidence for ADR-0004 and do not fail the gate. Nor does a page the driver doesn't reach in its 4 minutes: its DevTools figures are n/a (`missing: driver results`; PHASE_3_PLAN *As built (W6)*). The DevTools driver runs in the background for the whole group and needs the debug APK (WebView debugging is off in profile and release builds).

The large-file group works the same way: the test fails when a step cannot run (an open that fails or times out, the driver unable to measure, typed text that never reaches the app, a failed save), never on a budget. It asks the driver for each measurement in the device log (`LARGEGATE <run>.<n> prepare|measure|done`), and the driver answers with an empty file in the app's folder (`files/largegate/ack.<id>.ok` or `.failed`, written through `run-as`).

Every test run is bounded so a hang fails fast and says where. `test/flutter_test_config.dart` gives each widget test 2 minutes instead of the binding's default 10 (`flutter test --timeout` does not reach `testWidgets`). In CI, coreutils `timeout` caps the golden run at 10 minutes and the full suite at 15, which also catches a test that spins, where no per-test timeout can fire.

A widget test runs in a fake-async zone, so whatever its body awaits has to complete inside that zone. Code a test awaits must not await `StreamSubscription.cancel()`: it completes through a root-zone future. That resumes the test outside the zone's control, and the next thing it awaits never completes, so the test stalls until its timeout. For this reason `EditorHost.dispose()` stops its streams without awaiting them.

## 2. Fakes-first discipline

Every service interface ships with an in-memory fake in Phase 1. Widget/controller tests run against fakes — fast, deterministic, no device. Native implementations are validated by contract tests that run the **same test suite** against fake and native impls (interface contract tests), so divergence is caught mechanically.

## 4. Lifecycle & data-safety tests (non-negotiable)

- Kill process mid-edit → relaunch → buffer restored from journal, zero loss (Phase 2 gate; as built in W5: the edit pair and the zero-loss suites of §1.2).
- Rotate/split-screen/fold mid-edit and mid-terminal → state intact.
- Payload byte-flip → install fails typed, never marked ready (Phase 4 gate).
- DB migration N→N+1 with real fixture data (every schema change; harness `app/test/drift/app/`, where v1, the first version, checks its dump and a v1 fixture).
- Session close → zero orphan child processes (instrumented assertion).
